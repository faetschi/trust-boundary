About this mockup

This file is a static copy of the web chat as it runs at commit b7ec7e0 plus the uncommitted FX4 working tree (FX4). Each frame above is the running UI's root DOM, captured from /app/ on the demo gateway (--demo, session "Add /healthz and run tests") and placed under the built stylesheet of the same build (dist/assets/index-jsjcZe6r.css, verbatim). The only change to a frame is that its element ids get a per-frame prefix, so that two frames never share an id.

Frames are chosen by hash, for example #frame=chat-dark-390-dock-end. The five governance tabs swap the panel inside the frame that holds them, by mouse, by Enter or Space, and with Left, Right, Home and End. The Chat and Trajectory view tabs go to the matching frame at 1440 px. Nothing here uses the network, and no script loads anything.

Claim boundary. G1 is false, H1 is unexecuted, containment is not-established, and claim-bearing is false. Nothing in this mockup is evidence of G1 or H1. A static render checks layout and wording only.

The 390, 360 and 1024 px frames render at their own width only when the window is that width. The banner says so when it is not.

What changed since the first v3 mockup

  1. Sessions rail: one session, marked current, with the note "Other Pi sessions are not listed"; a strip when collapsed.
  2. Governance: five tabs, one panel at a time; choosing a tab closes a record.
  3. Messages: "Pi" and "User" labels, the time, Copy and the record number; each Copy has its own name.
  4. Composer: read-only and disabled, with the chips "Observed only · no approvals" and "Pi 0.87.1 · tools unavailable".
  5. Claim strip: the "Presentation only" and "Display only" lines, read from the projection.
  6. Absent versus zero: an absent count reads "unavailable", a stated zero reads "0" (see the states gallery).
  7. Lossy success: "output lossy, not counted as confirmed" on every surface that words a lossy success.
  8. State shapes: ALLOW bullseye, DENY square, LOST diamond; reported dashed, unknown dotted, pending hollow.
  9. Footer: the last box under the composer, at every width.
  10. Phones: the chat head sits 98 px below the header; the dock is sticky, and the footer follows it at the page end.
  11. Frames: 360 px and the phone dock-end states are new; the 1024 px drawer has a dark frame.
  12. Mockup: ids unique per frame; tabs switch without the network; the theme is set before first paint.

State vocabulary

Every shape carries a word (a chip), so no state is conveyed by colour alone. The shapes are drawn by StateDot.module.css and the chips by Chip.module.css. Both are copied unchanged, with class names prefixed.

  • succeededsolid circle: verified success (not reachable from the demo)
  • ALLOWbullseye: a 2 px ring with a centred dot. A permission, not an outcome
  • deniedsquare: refused, denied or failed. Not a success
  • reporteddashed ring: succeeded, not independently verified
  • unknowndotted ring: no terminal outcome retained
  • LOST, not successdiamond: the outcome was not recorded. Uncertain, not a refusal
  • pendinghollow ring: no outcome yet
  • unavailablesolid grey dot: no verdict or outcome, or not available

Differences from the running UI

  • Sample-only elements. The states gallery, the legend and the lossy and LOST samples are hand-written from the source. They are not in the demo, which has no LOST record, no lossy success and no absent count.
  • The "N new records" jump pill. It appears only when records arrive while the reader is scrolled away from the tail. No frame has it, so none is drawn.
  • Hover and focus. The comparison replays the pointer where the capture left it. The frames carry no focus except the composer frame's. A tab pressed in the mockup can leave the same 5-pixel corner difference.
  • Tab strip scrolling. The strip's scroll buttons are not operated here. Every captured tab strip fits its width.
  • Ids. Each frame's ids carry a prefix (chat-light-1440--…). No CSS selects by id, so the rendering is unchanged.
  • Former defect, fixed in FX4. At 390 and 360 px the composer's reason line was clipped with an ellipsis in FX3 (the Redesign QA defect 2). FX4 lets the reason wrap and makes the phone field two lines tall, so the frames show the full text.

Design notes

Token tiers. Tier 1 is the static ramp per theme (--tb-s-*; components never read it). Tier 2 is the alias layer components read (--background, --state-*, --source-*). Tier 3 is theme-free geometry (--space-*, --radius-*, --text-*). The values are copied verbatim from frontend/src/styles/tokens.css.

Type and shape. System font stacks only, with no webfonts. Colour is reserved for state and source. Hairline borders come before shadows.

What is not in this build, and so not drawn. A list of several sessions, a new-session control, sending, cancelling, mode menus, a diff stat, and MATCHED. The demo has one session.

Accessibility. Named landmarks in each frame: header "Workspace header", nav "Sessions and streams", main "Workspace", the governance aside, and the footer group "Session statistics". The governance and view tabs are role="tab" with aria-selected, in a tablist. The theme control is a group of buttons with aria-pressed. The Governance toggle carries aria-controls and aria-expanded. The status region is role="status". Focus is a visible ring. Reduced motion is switched off globally in base.css. In forced colours the state shapes keep their own borders.

Mockup mechanics. The frames and the built stylesheet are the running UI's own. The review, the gallery and the mock-only styles are hand-written. The Content Security Policy pins the two scripts and the one style block by hash, and allows nothing else, so the file makes no request.
