# tbound-op design (authoritative spec, 2026-10-21)

Source: runbook analysis of `infra/guest/PROVISIONING-SIGNING.md` (tb-integ, integ/real-host-20261020). Decision: Z1' = remove the NOPASSWD drop-in 90-tbound-tboundadmin and the lxd membership; keep tboundadmin in `sudo` WITH password (owner-only console root channel); add ONE NOPASSWD rule for `/opt/tbound/operator/tbound-op`. No unrestricted root for the automation after Z1'.

## Findings that shape the design
1. The tbound-op rule is an explicit exception to the runbook's Z1 text; the Z1 acceptance becomes "only the single tbound-op rule is listed (plus password-protected %sudo)".
2. A caller-supplied digest only proves the file matches what the caller said. Anchors: signed artifacts under /etc/tbound/pi-host-profile.pub; unsigned inputs (config, template, manifest, tbound-profile, test binaries, run.json) via a root-owned /opt/tbound/operator/pins.env (F, TBOUND_DIGEST, TBP_DIGEST, BUNDLE_DIGEST, BASE_TD, IMGDIGEST, ADMIN_PUB_DIGEST, SRC_DIGEST, CFG) and via the signed binding chain (registration binds the config digest, profile binds the template digest TD, pilot config binds the corpus digest). For the config also check structure: the staged config must equal the shipped template for that NAME with only containers_conf_digest/storage_conf_digest (== sha256 of installed podman-config files), the admission id (dr only) and the corpus digest (pilot only) differing.
3. Staged files live in tboundadmin's dir: open with O_NOFOLLOW (regular file, owner tboundadmin, size cap), copy into a root-only tmpfs work dir (0700), hash/verify the copy, install from the copy. Fixed staged file names per verb; no path arguments.
4. The forced client key accepts only corpus-mode requests; smoke, G1, rp, dr client calls need a root verb (setpriv --reuid 994).
5. Confirm config/registration field names in the code (supervisor) before use.
6. Journal access after Z1': tboundadmin keeps group adm; confirm the journal is persistent.

## Inventory of post-Z1 root actions (runbook)
L0 seed smoke fixture; L1 start service; L3 smoke client (setpriv 994/985, `tbound serve --pi --task-id smoke-read-readme --task-request-id $RID --task "$PROMPT" --bash-no-outputs`, PROMPT = installed config workflow_prompt); L4 reads of audit/catalog/podman ps; L5 negatives N2 (`setpriv --reuid 1000 --regid 1000 --clear-groups python3 -c 'import socket; s=socket.socket(socket.AF_UNIX); s.connect("/run/tbound/serve-pi.sock")'`), N5 (CLIENT with --native-host-profile / --workspace / --source -> refused), N6 (setpriv --reuid 1000 --regid 985 ... refused), N7 (L3 with --task-id smoke-unknown-task and fresh RID7 -> unknown); operator recovery (`systemctl stop tbound-pi.service tbound-pi.socket; tbound abandon-unknown --request-id $RID7 --reason "N7 smoke negative: unknown task id, no workflow started"; systemctl start tbound-pi.socket`).
RG cycle per NAME in {g1, rp, dr, pilot}: RG-2 install config (backup to /root/ga/prev/<NAME>/); RG-3 measure registration (create /sys/fs/cgroup/system.slice/tbound-pi.service with "+cpu +memory +pids" and chown 995:986 of dir, cgroup.procs, cgroup.threads, cgroup.subtree_control; `/usr/local/bin/tbound-profile managed-root-measure --root /var/lib/tbound/live/root --service-name tbound-pi --service-group tbound-pi --service-unit /etc/systemd/system/tbound-pi.service --mount-unit /etc/systemd/system/var-lib-tbound-live.mount --runner /usr/local/bin/tbound --service-cgroup /system.slice/tbound-pi.service --allowed-client-uids 994 --allowed-client-primary-gid 985 --out /root/ga/reg-<NAME>/managed-live-root.unsigned.json`; rmdir the cgroup); RG-5 install registration (+ managed-root-verify under /etc/tbound/pi-host-profile.pub); RG-7 install profile, signature, template (verify; template-digest TD == profile ContainmentProfileDigest; archive /etc/tbound/{pi-host-profile.json,pi-host-profile.ed25519,pi-host-profile.pub,managed-live-root.json,managed-live-root.ed25519,serve-pi-service.json} into /root/ga/<NAME>/; template as /root/ga/<NAME>/d09-cell.json, for dr the installed probe template as /root/ga/dr/d09-cell.route-probe.json plus the staged production template as /root/ga/dr/d09-cell.json); RG-8 start service (service is socket-activated: tbound-pi.socket must be active), stop at run end (service and socket).
G1-3 seed: `rm -f /var/lib/tbound/live/root/SMOKE-README.txt; install -d -o 995 -g 986 -m 0755 /var/lib/tbound/live/root/src /var/lib/tbound/live/root/out; printf 'version=2.4.0\nstatus=draft\n' | install -o 995 -g 986 -m 0644 /dev/stdin /var/lib/tbound/live/root/src/release.txt` + listing + census. G1-4 client: task g1-read-edit-bash-read, `--bash-output out/release.sha256`, output /root/ga/out/response.txt. rp client: task route-probe-bash-view, `--bash-no-outputs`, output /root/ga/out/probe-response.txt. dr: same probe config with a new admission id; RUNID = run id of the new *-session-audit.jsonl.
Part D D2: install /etc/tbound/corpus/manifest.json (root 0644, <=16 MiB, dir root 0755) after `tbound-profile corpus-digest --manifest <copy> --quota-profile pilot --artifacts /opt/tbound/corpus/artifacts --max-host-calls 17 --max-tokens 20000 --duration-seconds 1200` equals the caller's CORPUS_DIGEST.
Guest EVQ producers (TBPG = /root/ga/tbound-profile guest-evidence, from /root/ga, --commit $F): capability (`--seccomp-profile /opt/tbound/cell/seccomp.json --out /root/ga/out/capability.json`), netsink (`--out /root/ga/out/netsink.json`), landlock-connect (`tests --kind guest-tests-landlock-connect --test-binary /root/ga/tbound-cell-entrypoint.test --out ...`), procoracle (`tests --kind guest-tests-procoracle --test-binary /root/ga/procoracle.test --out ...`), provider-exchange (`--response /root/ga/out/response.txt --run-config /root/ga/run.json --template /root/ga/g1/d09-cell.json --host-profile /root/ga/g1/pi-host-profile.json --host-profile-signature /root/ga/g1/pi-host-profile.ed25519 --host-profile-key /root/ga/g1/pi-host-profile.pub --registration /root/ga/g1/managed-live-root.json --registration-signature /root/ga/g1/managed-live-root.ed25519 --out /root/ga/out/provider.json`), route-bash-view (`route-denied --route bash-view --run-id $RUNID --response /root/ga/out/probe-response.txt --target /home/node/.profile --control-path src/release.txt --control-file /var/lib/tbound/live/src/release.txt --run-config /root/ga/run.json --template /root/ga/rp/d09-cell.json --host-profile /root/ga/rp/pi-host-profile.json --host-profile-signature /root/ga/rp/pi-host-profile.ed25519 --host-profile-key /root/ga/rp/pi-host-profile.pub --registration /root/ga/rp/managed-live-root.json --registration-signature /root/ga/rp/managed-live-root.ed25519 --out /root/ga/out/route-bash-view.json`), route-direct-runtime (`route-denied --route direct-runtime --run-id $RUNID --target /home/node/.profile --control-path src/release.txt --run-config /root/ga/run.json --probe-template /root/ga/dr/d09-cell.route-probe.json --production-template /root/ga/dr/d09-cell.json --host-profile /root/ga/dr/pi-host-profile.json ... dr registration ... --out /root/ga/out/route-direct-runtime.json`).

## Dispatcher
Invocation: /opt/tbound/operator/tbound-op (root:root 0755, dir 0755); sudoers `tboundadmin ALL=(root) NOPASSWD: /opt/tbound/operator/tbound-op` + `Defaults!/opt/tbound/operator/tbound-op env_reset,!setenv`. Preamble: bash, set -euo pipefail, umask 077, fixed PATH, LC_ALL=C, unset BASH_ENV ENV, absolute tools, no eval, anchored [[ =~ ]] arg checks + no-newline check; unknown verb/surplus args exit 2. flock /run/tbound-op.lock. Log argv, $SUDO_USER, result to /var/log/tbound-op.log root:adm 0640. pins.env check: ADMIN_PUB_DIGEST == sha256(/etc/tbound/pi-host-profile.pub). State /root/ga/state/<NAME> (config, reg, prof, started, client-run-done); a second client-run per NAME refused (admission one-use). Staged input ~tboundadmin/stage-<NAME>/<fixed filename>. Outputs /var/tmp/tbound-op/<NAME>/ (or _) root:tboundadmin 0750, files 0640; never the provider key, netsink.secret or /root/.ssh. Backups /root/ga/prev/<NAME>/<file> write-once. Installs atomic (.new + mv -f); already-equal = no-op success.
Grammar: NAME := smoke|g1|rp|dr|pilot; SHA := ^(sha256:)?[0-9a-f]{64}$; RUNID := ^[A-Za-z0-9._-]{8,128}$ and /var/lib/tbound/audit/<RUNID>-session-audit.jsonl must exist; RID generated by the dispatcher ^(smoke|g1|rp|dr)-req-[0-9]{8}T[0-9]{6}Z$.
Verbs:
- cfg-install NAME SHA — service inactive; copy+hash; structural compare vs shipped template (finding 2); backup; install 0644; state=config.
- reg-measure NAME — state=config, installed config sha == recorded; service inactive, cgroup absent; create cgroup (trap removes); measure to /root/ga/reg-<NAME>/ (refuse if exists); check runner_digest == pins TBOUND_DIGEST, uid 995, config digest == installed; copy to output dir.
- reg-install NAME SHA_JSON SHA_SIG — copy+hash; managed-root-verify --pub /etc/tbound/pi-host-profile.pub --runner-digest pins TBOUND_DIGEST; config digest == installed config; backup; install; re-verify; record REGDIGEST; state=reg.
- prof-install NAME SHA_PROFILE SHA_SIG SHA_TEMPLATE [SHA_PRODTEMPLATE (dr only, required)] — copy+hash; tbound-profile verify --runtime-bundle-digest pins; template-digest: TD == profile ContainmentProfileDigest, BASE_TD == pins, template registration digest == installed REGDIGEST, image == IMGDIGEST; dr production template == probe template minus route_probe, same BASE_TD; backup; install; re-verify; archive to /root/ga/<NAME>/ per RG-7; sha list to output; state=prof.
- adopt smoke — verify the currently installed smoke config/registration/profile/template exactly as prof-install would; archive to /root/ga/smoke/; state=started if the service is active.
- rollback NAME cfg|reg|prof|all — service inactive; restore from prev; re-verify; missing backup = fail.
- manifest-install SHA CORPUS_DIGEST — D2 as above.
- svc start|stop — stop: service and socket; start: requires state>=prof for the installed NAME (installed config sha == recorded), start socket then service, save journal tail to output.
- seed-live smoke|g1 — service inactive (for g1) / any (smoke idempotent); fixed contents; listing + census to output.
- client-run smoke|g1|rp|dr — service active, state started for that NAME, no prior client-run; generate RID; task id + bash flag from a fixed mapping cross-checked with the installed config; setpriv 994/985 client; run detached, status file; output /root/ga/out/{response,probe-response}.txt mirrored to output dir; mark client-run-done. `status` shows progress.
- negative n2|n5|n6|n7 — fixed lines as written; output to dir.
- abandon RID --confirm <12 hex of sha256 of the printed L4 fact list> — prints facts first; then stop service+socket, abandon-unknown with fixed reason, start socket.
- guest-evidence capability|netsink|landlock-connect|procoracle|provider-exchange|route-bash-view|route-direct-runtime [RUNID] — hardwired flags; preconditions on test binary / tbound-profile / run.json digests; refuse existing out; copy result to output.
- stage-ga tbound-profile|procoracle-test|cell-entrypoint-test|run-json SHA — copy+hash+pin compare; install 0500 (run.json 0444) to /root/ga/.
- collect l4|evidence-out|audit RUNID|requests|catalog — allow-listed copies to output dir.
- diag l2|mounts|census-live|podman-ps|podman-ps-noreap|nft-sink|probe-capabilities|image-probe|live-listing|netsink-journal-size — fixed read-only wrappers.
- spikeb nft-delete|net-sink-rmdir|reboot (optional), netsink-rotate, provider-key (optional, tty only), status [NAME].

## Owner-only (not verbs)
Account/sudo/ssh changes; binary/mount reinstalls (runner swap, podman/crun/git upgrades); provider key entry (except tty-only provider-key); N1 concurrency test; Spike B ad hoc probes; recovery from half-applied cycles; anything needing the owner key (signing happens on the owner machine); any arbitrary-command escape (none by design).

## Read-only after Z1' without root
journalctl (adm), systemctl status, cgroup reads, findmnt/sha256sum/stat of /etc/tbound, tbound-profile verify/managed-root-verify/template-digest/corpus-digest on /etc/tbound files, flock check of the maintenance lock, ps -u 995, evidence/trial forced keys, tbound-run via the three forced keys. Audit/catalog/requests, podman ps, nft need the dispatcher.
